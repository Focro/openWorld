# ИИ и ключи игроков (0.13.0)

## Схема
Браузер → **наш прокси** (`server/ai-proxy.mjs`) → провайдер.

Провайдеры: **Claude** (официальный SDK `@anthropic-ai/sdk`), **OpenAI**, **DeepSeek**, **OpenRouter** (OpenAI-совместимый `/chat/completions`). Игрок выбирает нейросеть в «Системе». Сохранённый ключ привязан к своему провайдеру, поэтому ключ OpenAI не уйдёт в DeepSeek. Свою модель можно указать только со своим ключом; с ключом сервера модель задаёт сервер (контроль расходов). Ключ сервера никогда не попадает в браузер. Модель возвращает только JSON-предложение действия, движок его проверяет.

## Два режима
1. **Ключ сервера.** `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` / `DEEPSEEK_API_KEY` / `OPENROUTER_API_KEY` в секретах хостинга. Расходы ограничены лимитами прокси.
2. **Свой ключ игрока.** Вводится на вкладке «Система», шифруется паролем игрока:
   - PBKDF2-SHA-256, 310 000 итераций, случайная соль → ключ AES-GCM-256, случайный IV; имя провайдера в AAD.
   - В `localStorage` лежит только шифротекст. Пароль не хранится нигде; забыл пароль — ключ надо ввести заново.
   - После разблокировки ключ живёт только в памяти вкладки (`UnlockedKeySession`, приватные поля, не сериализуется).
   - Ключ уходит одним заголовком `X-Player-Api-Key` и только на HTTPS или localhost. Прокси его не логирует и не сохраняет.

## Честные ограничения
- Если у игрока свой ключ, он неизбежно проходит через его браузер. XSS или вредное расширение могут его перехватить в момент использования. Поэтому: строгий CSP на хостинге, никаких сторонних скриптов, лимиты на прокси, а игроку — ключ с лимитом расходов в консоли провайдера.
- Для «аккаунтов» с синхронизацией ключа между устройствами нужен свой backend с авторизацией; это следующий этап.
- GitHub Pages отдаёт только статику: прокси надо разворачивать отдельно (любой Node-хостинг), а в игре указать его адрес.

## Запуск локально
```bash
cd server && npm install
ANTHROPIC_API_KEY=... AI_ALLOWED_ORIGINS=http://localhost:5173 npm start
```
Переменные: см. `.env.example`. Модели по умолчанию: Claude — `claude-opus-5-5` (effort `low`), DeepSeek — `deepseek-chat`; для OpenAI и OpenRouter модель задаётся в `AI_OPENAI_MODEL` / `AI_OPENROUTER_MODEL` или игроком со своим ключом. Реальные вызовы провайдеров в среде разработки не проверялись (нет ключей), проверены форма запросов и разбор ответов.

## Что не делать
- Не класть ключи в `VITE_*`, исходники, git, сохранения игры.
- Не отключать проверку действий движком «ради удобства».
